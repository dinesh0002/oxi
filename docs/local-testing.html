Testing Oxi against local services

For the owner's own tests. Each service runs in a local Docker container from tests/docker/compose.yml in the app repository, and every port binds to 127.0.0.1. Use the values below in Oxi's connection form (Connections, then Add connection).

Before you start

  • Run every command from the root of the app repository (oxicore).
  • Start only the services a test needs. Stop them as soon as the tests finish: docker compose -f tests/docker/compose.yml stop.
  • The test passwords below are defaults for throwaway containers. Overrides: OXI_TEST_PG_PASSWORD, OXI_TEST_MSSQL_PASSWORD, OXI_TEST_CLICKHOUSE_PASSWORD. The Postgres reader password is fixed in postgres-init.sql.
  • Remove containers and their data with docker compose -f tests/docker/compose.yml down -v. Seeds run again on the next start.
  • Never point these connections at real data.

SSH bastion (tunnel to Postgres)

start
$ docker compose -f tests/docker/compose.yml up -d --wait postgres ssh-bastion

The bastion reaches the database as postgres:5432 on the compose network. Use the Postgres form with these changes:

Connection idssh_pg
Hostpostgres (the database's name on the compose network, not 127.0.0.1)
Port5432
Database, user, passwordshop, oxi_reader, oxi_reader_pg
SSH host127.0.0.1
SSH port52222
SSH useroxi
Key fileThe absolute path of tests/docker/ssh/id_ed25519 on this machine (a test key, no passphrase)
Key passphraseLeave empty

The first test shows the bastion's host-key fingerprint on the card. Check it, then use the trust button on the card. Oxi refuses any other key for this host. A new connection to a host you have not trusted connects to nothing.

stop
$ docker compose -f tests/docker/compose.yml stop ssh-bastion postgres

Rust gated test: OXI_TEST_SSH=1 cargo test -p oxicore-core ssh_tunnel_through_docker (needs Postgres and the bastion running).

Fake GCS (blocked)

Status: blocked. The service seeds, but DuckDB's GCS secret uses the XML (S3-compatible) API, which fake-gcs-server does not serve. Oxi cannot read from it yet, so do not add a Google Cloud Storage connection for this service. The emulator test in tests/service.rs is marked blocked for the same reason.

If you start it for seeding: docker compose -f tests/docker/compose.yml up -d --wait fake-gcs fake-gcs-seed. Stop with stop fake-gcs.

SQLite and DuckDB fixture files

No container is needed. Both files are in the app repository.

SQLiteFile fixtures/workspace-plain/shop.sqlite, one table orders. Kind SQLite, file path shop.sqlite (relative to fixtures/workspace-plain, which is the workspace you open).
DuckDBFile fixtures/workspace-dbt/warehouse.duckdb. Open fixtures/workspace-dbt as the workspace, then kind DuckDB and file path warehouse.duckdb. If the file is missing, rebuild it: cargo run -p oxicore-core --example gen_fixtures.
