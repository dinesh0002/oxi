// why oxi

Why Oxi

Your data. Your laptop. Fast answers.

Dashboards bill per query, keep metrics in two places and upload your extracts. Oxi runs the same work on your machine.

  • 01 · data stays local

    Nothing leaves your machine.

    No uploads, no telemetry, no network calls. Queries run in embedded DuckDB on your own CPU.

  • 02 · no server

    Open a folder and query it.

    Parquet, CSV, JSON, Excel and DuckDB files appear as datasets. No server or warehouse to set up.

  • 03 · fast on a laptop

    100M rows, 5.6 s uncached.

    Dashboard reloads on an M1 Mac with 8 GB RAM. Cached reloads take under 1 ms on the backend, and peak memory stays under 400 MB.

  • 04 · one set of numbers

    Metrics defined once.

    Semantic models are dbt-compatible YAML, validated live, with OSI import and export. Open formats, no lock-in.

  • 05 · safe by default

    Read-only, SELECT only.

    Data files open read-only. The SQL console accepts only SELECT, and queries cannot read files outside the workspace.

  • 06 · reuse what you have

    Bring your dbt projects and files.

    Use existing dbt projects, plus Parquet, CSV and Excel files. Coming: secure connections to Postgres, Snowflake, BigQuery and other databases.

// product

Four parts. One local engine.

Connect your files, describe them once, and build dashboards on top. Everything runs on the laptop in front of you.

01

Catalog

Point it at folders. Oxi reads Parquet, CSV/TSV, JSON/NDJSON, Excel and DuckDB files, and shows them as datasets.

  • Hive-partitioned folders and same-shaped files show as one dataset
  • Nested JSON and NDJSON, including gzip and zstd
  • Explore a dataset without leaving the catalog

02

Semantic models

Models live in dbt-compatible YAML, with MetricFlow-style metrics, entities and joins. Generate one from a dataset in one click.

  • Simple, ratio, derived, cumulative and conversion metrics
  • Validated live as you edit
  • OSI (open semantic interchange) import and export

03

Dashboards

Ten card types, slicers and cross-filter, with drill-through pages for the detail behind every number.

  • Quick measures: YoY % and % of total
  • A live performance panel records every reload's timing
  • Cached reloads return in under a millisecond

04

Secure by design

Local-first. No telemetry and no network calls, so your data never leaves the laptop.

  • The SQL console is SELECT-only and cannot read files outside the workspace
  • Coming: read-only connections, credentials in the OS keychain, PII detection

// architecture

Local-first, end to end

A Rust core reads your files, plans the work, and hands queries to DuckDB. The UI sits on top in a Tauri shell. Nothing crosses the network.

// workflow

From files to a dashboard in minutes

Four steps. Each takes under 20 seconds on screen.

  1. 01

    Point at a folder < 20 s

    Catalog lists each file as a dataset, with row count and schema.

  2. 02

    Generate a model < 20 s

    One click drafts dbt-compatible YAML from the columns. The validator marks it Valid.

  3. 03

    Explore and query < 20 s

    Preview and profile the data, or write SQL. Save any result as a card.

  4. 04

    Build the dashboard < 20 s

    Add slicers, cross-filter cards and drill through. Cached reloads take 0.4–0.5 ms on the backend.

Based on the recorded demos on an M-series Mac with the sample data. Each step is under 20 s of screen time; the clips were recorded at a deliberately slow pace.
